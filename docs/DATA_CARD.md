# Synthetic demonstration data card

## Summary

The default PlayerPulse dataset is deterministic, fictional, and generated by
project code with seed `20260720`. It represents one 20-player match across two
fictional teams and two shortened periods. It exists to demonstrate software
behavior—not real football performance or human physiology.

Every generated tracking/event row and persisted match carries
`is_synthetic=true`. Names use the form `Synthetic Player NN`; teams and the
competition are visibly fictional.

## Included patterns

The generator creates reproducible player paths, workload variation, sprint
bouts, supported football events, and a bounded missing-coordinate segment.
Those patterns exercise cleaning, interpolation, movement features, fixed
windows, event metrics, data-quality reporting, persistence, charts, baselines,
and rule explanations.

## Appropriate uses

- Automated tests and CI
- Local/public demo journeys
- Documentation and portfolio screenshots
- Performance and schema regression checks

## Inappropriate uses

- Clinical, medical, injury, treatment, or return-to-play decisions
- Validation of physiological thresholds or model accuracy
- Claims about a real player, team, provider, or competition
- Training a production model intended for real athletes

## Quality and reproducibility

Generation is covered by determinism and cache-isolation tests. The processing
pipeline reports coordinate completeness, timestamp validity, plausible-speed
rate, exclusions, interpolation, limitations, and a quality score. A quality
score describes input support only; it does not validate the underlying
football or sports-science interpretation.

## Rights and privacy

PlayerPulse contributors own the synthetic generator. No real identity,
biometric, health, or third-party raw football data is included. Optional
provider adapters remain rights-gated and local-import-only as documented in
`DATASET_ATTRIBUTION.md`.
